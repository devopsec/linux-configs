## 1. Versions & install (VMs)

- Reference pins checked 2026-10-28 against [Prometheus downloads](https://prometheus.io/download) and [Grafana releases](https://github.com/grafana/grafana/releases): Prometheus **3.15.0** (or **3.13.4 LTS**), Alertmanager **0.34.1**, and Grafana **13.2.4**. Prometheus 3 changes from 2.x: new UI, UTF-8 metric names, feature-flag changes, and stable native histograms — run `promtool check config` after upgrade.
- Install: distro packages if current enough, otherwise release tarball + checksum:

```bash
ver=3.15.0   # reference pin checked 2026-10-28
curl --fail --location --remote-name "https://github.com/prometheus/prometheus/releases/download/v${ver}/prometheus-${ver}.linux-amd64.tar.gz"
curl --fail --location --remote-name "https://github.com/prometheus/prometheus/releases/download/v${ver}/sha256sums.txt"
sha256sum --check --ignore-missing sha256sums.txt
```

  Run as a dedicated `prometheus` user via a systemd unit managed with the deployment mechanism already used for the service. Grafana: official signed rpm/apt repo (`rpm.grafana.com` / `apt.grafana.com` with GPG key).
- Flags: `--storage.tsdb.retention.time=30d` (and/or `.size`), `--web.listen-address=<private-ip>:9090`, `--web.enable-lifecycle` only if the endpoint is protected.
- Protect UIs: Prometheus `--web.config.file` (basic auth bcrypt hash + TLS) or bind to loopback behind IAP/VPN. Grafana: no anonymous admin; admin password from Secret Manager via `GF_SECURITY_ADMIN_PASSWORD__FILE=/run/secrets/grafana_admin`.
- Firewall: allow 9090/9093/3000 only from the operator network; exporters only from the Prometheus host.

## 2. Scrape config & service discovery on GCE

See `assets/prometheus.yml`. Key pattern — discover VMs by label instead of static IPs:

```yaml
- job_name: node
  gce_sd_configs:
    - project: <project-id>
      zone: <zone>
      port: 9100
      filter: 'labels.prometheus = "true"'
  relabel_configs:
    - source_labels: [__meta_gce_instance_name]
      target_label: instance
    - source_labels: [__meta_gce_label_role]
      target_label: role
    - source_labels: [__meta_gce_private_ip]
      target_label: __address__
      replacement: '$1:9100'
```

Prometheus VM's service account needs `roles/compute.viewer`. Alternative: `file_sd_configs` generated by install scripts/OpenTofu.

## 3. Exporters

| Target | Exporter | Notes |
|---|---|---|
| Linux host | `node_exporter` | `--collector.systemd` to watch unit states; textfile collector for cron/backup results |
| PostgreSQL (VM) | `postgres_exporter` (prometheus-community) | DSN from env file `DATA_SOURCE_NAME` (0600); role `IN ROLE pg_monitor` |
| Cloud SQL | Cloud Monitoring metrics (no exporter) | query via Managed Prometheus/Grafana Cloud Monitoring datasource |
| Instrumented service | Prometheus client endpoint | expose only the metrics needed for service health; protect the endpoint |
| systemd services | `node_exporter --collector.systemd` or `process-exporter` | |
| Blackbox (HTTP/TLS endpoint checks) | `blackbox_exporter` | use a purpose-specific module and approved target list |

## 4. PromQL essentials

```promql
rate(http_server_request_duration_seconds_count[5m])                 # per-second rate (counters only)
sum by (status_class) (rate(http_requests_total[5m]))
histogram_quantile(0.95, sum by (le, route) (rate(http_server_request_duration_seconds_bucket[5m])))
1 - avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m]))
1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes
predict_linear(node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"}[6h], 24*3600) < 0   # disk full within 24h
node_systemd_unit_state{state="failed"} == 1
absent(up{job="backend"})                                                               # target vanished
```

Rules of thumb: `rate()` before `sum()`; `rate` window ≥ 4× scrape interval; quantiles from aggregated buckets, never `avg` of quantiles; ratios: aggregate numerator and denominator separately.

## 5. Recording & alerting rules

See `assets/alert-rules.yml`. Conventions: record names `level:metric:operations` (e.g. `job:http_requests:rate5m`); every alert has `severity`, `team`/`service`, `summary`, `runbook_url`. Ratios use `humanizePercentage` (value 0–1), not `printf "%.2f%%"` (upstream bug).

Test rules: `promtool check rules rules/*.yml` and unit tests with `promtool test rules tests/*.yml`.

## 6. Alertmanager

```yaml
route:
  receiver: chat-default
  group_by: [alertname, service]
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  routes:
    - matchers: [ 'severity="page"' ]
      receiver: pager
      repeat_interval: 1h
    - matchers: [ 'severity="ticket"' ]
      receiver: chat-default
      active_time_intervals: [business-hours]
receivers:
  - name: chat-default
    webhook_configs:
      - url_file: /etc/alertmanager/secrets/chat_webhook_url     # secret on disk (0600), not inline
  - name: pager
    pagerduty_configs:
      - routing_key_file: /etc/alertmanager/secrets/pd_routing_key
inhibit_rules:
  - source_matchers: [ 'severity="page"' ]
    target_matchers: [ 'severity="ticket"' ]
    equal: [service]
time_intervals:
  - name: business-hours
    time_intervals:
      - weekdays: ['monday:friday']
        times: [ { start_time: '09:00', end_time: '17:00' } ]
        location: <IANA tz>
```

- `match`/`match_re` are deprecated → `matchers`. Prefer `*_file` fields (`url_file`, `routing_key_file`, `api_key_file`) for secrets.
- `amtool check-config alertmanager.yml`; test routing: `amtool config routes test --config.file=alertmanager.yml severity=page service=<service>`.
- HA: run 2–3 Alertmanagers with `--cluster.peer`; point Prometheus at all of them.

## 7. Grafana provisioning & backups

```yaml
# /etc/grafana/provisioning/datasources/prometheus.yaml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://<prometheus-host>:9090
    isDefault: true
    editable: false
```

```yaml
# /etc/grafana/provisioning/dashboards/default.yaml
apiVersion: 1
providers:
  - name: default
    folder: Platform
    type: file
    allowUiUpdates: false
    options: { path: /var/lib/grafana/dashboards, foldersFromFilesStructure: true }
```

- Dashboards as code: JSON in VCS (export via `scripts/grafana-backup.sh`), or Grafana's Git Sync / Terraform `grafana` provider. Use datasource **template variables** (`${datasource}`), not hardcoded UIDs.
- Community dashboards: Node Exporter Full and PostgreSQL (postgres_exporter); review all imported queries and labels before use.
- Service-account tokens (not legacy API keys) with Viewer role for backups; store token in Secret Manager → env `GRAFANA_TOKEN`.

## 8. Managed alternatives on GCP

- **Managed Service for Prometheus** (GMP): self-deployed collection = run upstream-compatible `prometheus` binary from Google with `--export.*` flags, or OTel `googlemanagedprometheus` exporter / Ops Agent `prometheus` receiver. Query with PromQL in Cloud Monitoring or Grafana (Prometheus datasource → GMP frontend).
- **Cloud Monitoring alerting policies** support PromQL conditions — manage with OpenTofu (`google_monitoring_alert_policy`) → `infra-gcp-any-manage`.
- Choose one alert evaluator per signal to avoid duplicate pages.

## 9. Troubleshooting

| Symptom | Check | Fix |
|---|---|---|
| target `down` | `scripts/prom-health-check.sh`, `curl` from Prom host | firewall/bind address, exporter unit status |
| high memory / slow queries | `prometheus_tsdb_head_series`, top series: `topk(10, count by (__name__) ({__name__=~".+"}))` | drop labels via `metric_relabel_configs`, recording rules |
| gaps in graphs | scrape duration > interval | raise `scrape_timeout`/interval, slim exporter |
| alert never fires | `promtool test rules`, `for:` too long, wrong labels | fix expr, check Alertmanager routing with `amtool` |
| duplicate notifications | multiple Alertmanagers not clustered | `--cluster.peer` |
