# Zig development

Zig is pre-1.0 and breaks its standard library every minor release. Model memory of Zig is mostly
0.11–0.13 era and **wrong** for 0.15+ (`std.io`, managed `ArrayList`, `std.fs.cwd()`, `std.net`,
`@cImport`, `std.Thread.Mutex`, …). Every API you write must be checked against the installed
compiler's std source.

## Ground rules

- **Version first.** Run `scripts/zig-env.sh <project>` before writing code. Target the
  project's pinned series (`build.zig.zon` `.minimum_zig_version`); if it differs from the
  installed compiler (exit 3), stop and ask which to target — do not silently port.
- **Verify, don't recall.** Before using any std API you have not verified this session, run
  `scripts/std-find.sh <name> [path-filter]` (add `-b` for struct fields / bodies, `-d` for doc
  comments). Language questions: `scripts/langref.sh '<section>'`. Copy patterns from
  `<lib_dir>/init/` templates and std's own tests over community snippets.
- Source of truth order and known-bad community advice: [sources](references/sources.md).
  Upstream lives on **Codeberg** (`codeberg.org/ziglang/zig`), not GitHub.
- Match the code base: its Zig version, allocator conventions (`gpa`/`arena` naming, unmanaged
  containers), error-set style, and `zig fmt` output. No new dependencies without asking.
- Never use libc/pthreads to dodge `std.Io` (threads, sleep, time, random) — pass `io` through.
- Keep safety on: no `@setRuntimeSafety(false)`, `catch unreachable` on fallible I/O or
  allocation, or `ReleaseFast` defaults unless the user asks and it is measured.

## Workflow

1. **Classify the task** and load only the matching references:

   ```sadkitti
   REFERENCE "references/sources.md"
   IF writing or changing Zig source (syntax, types, errors, comptime, casts)
     REFERENCE "references/language.md"
   IF task touches main(), files, stdout/stderr, formatting, readers/writers, time, random, threads, sockets, child processes, args, env
     REFERENCE "references/io.md"
   IF task allocates memory or uses containers (ArrayList, HashMap, arenas, pools)
     REFERENCE "references/allocators.md"
   IF task touches build.zig, build.zig.zon, dependencies, zig fetch, cross-compilation, install steps
     REFERENCE "references/build.md"
   IF task touches C headers, C libraries, extern/export, callconv(.c), zig cc
     REFERENCE "references/c-interop.md"
   IF task adds tests or fuzzers, or is a compile error, panic, leak, or hang
     REFERENCE "references/testing.md"
   IF installed or pinned version is older than 0.17 or code uses pre-0.17 APIs
     REFERENCE "../dev-zig-version-migrate/SKILL.md"
   ```

   References describe 0.17. For an older pinned series, use the migration skill's per-version
   notes to translate (they list what each version added/removed), and verify with `std-find.sh`.

2. **Check the toolchain** (read-only): `scripts/zig-env.sh [project]` — compiler, `std_dir`,
   local langref, ZLS, pinned version. No compiler installed → tell the user; suggest their
   package manager / `mise use zig@<ver>` / official tarball from
   <https://ziglang.org/download/>; do not install without approval.

3. **Discover before writing.** For each std API, builtin, or build function you plan to use:
   `scripts/std-find.sh` / `scripts/langref.sh`. New projects: `zig init` (or copy the
   `<lib_dir>/init/` templates) instead of hand-writing `build.zig.zon` — the fingerprint must
   be generated by Zig.

4. **Design types first.** Data structures, error sets, and function signatures before bodies:
   tagged unions over optional-field structs, explicit error sets on public APIs, allocator
   and `io` as explicit parameters, ownership documented in doc comments.

5. **Implement incrementally** and compile after each step (`zig build` or
   `zig build-obj -fno-emit-bin file.zig` for a single file). Read the *first* error and its
   reference trace (`-freference-trace`) before changing anything.

6. **Test.** Every new function with logic gets a `test` block in the same file using
   `std.testing.allocator` (leak-checked) and `std.testing.io`. Allocation-heavy code:
   `checkAllAllocationFailures`. Parsers/decoders: a fuzz test.

7. **Verify** before reporting done:
   `scripts/check.sh [project|file.zig] [-- -Dtarget=…]` → `zig fmt --check`, build, `zig build test`.
   Report the stages that ran and their results; if no compiler was available, say the code is
   unverified and list the APIs you checked against std source instead.

## Scripts

| Script | Purpose |
|---|---|
| `scripts/zig-env.sh [-f field] [dir]` | toolchain + pinned version; exit 3 on series mismatch |
| `scripts/std-find.sh [-d] [-b] [-a] <regex> [path]` | find pub decls in the installed std with signature/doc/body |
| `scripts/langref.sh [-l] [-u ver] <section>` | langref section as text (local, or fetched for a version) |
| `scripts/check.sh [-F] [-T] [-r mode] [target] [-- args]` | fmt → build → test gate with timeouts |

All scripts honor `ZIG=/path/to/zig` for non-PATH or side-by-side compilers.

## Done checklist

- [ ] Code targets the project's pinned Zig series; every std API was checked this session.
- [ ] `zig fmt` clean; builds without warnings-as-errors failures; tests pass with zero leaks.
- [ ] Every allocation has a matching `defer`/`errdefer`; ownership documented on public APIs.
- [ ] No `catch unreachable` / `.?` / `@intCast` on untrusted input without a guard.
- [ ] Buffered writers flushed; `io` and allocators passed, not created inside libraries.
- [ ] `.gitignore` covers `.zig-cache/`, `zig-out/`, `zig-pkg/` for new projects.
